# Composition, Not Selection — replication materials

Code and result artifacts for *Composition, Not Selection: What Gender Gaps in Venture Capital Track Records Measure*. The paper attributes 154,123 venture investments (2010–2023, Crunchbase) to individual partners and asks what the measured exit gap on female partners' female-founded deals measures — deal composition or selection — using within-cell location ladders, a within-partner outcome test, a deal-fixed re-investment design, undiluted balance tests, stacked event studies around partner turnover, and a decomposition of track records into composition and selection.

**Outputs are stored in the first three notebooks**, so every table and figure is visible on GitHub without installing anything or obtaining any data. They read only the aggregate result artifacts in `artifacts/` — no microdata is used or required. The table and figure cells are **cut verbatim from `code/build/p001_09_exhibits.py`**, the script that generated the exhibits attached to the manuscript, so the notebooks cannot drift from the paper's code; the last cell of each notebook raises if anything differs from `paper_exhibits/`.

To re-execute: Python 3.11+, `numpy`, `pandas`, `matplotlib`. Run from inside `notebooks/`, or rebuild the notebooks with `python code/build/make_notebooks.py`.

## How a number in the paper is traced

Every reported number has a row in `artifacts/CLAIMS_LEDGER.csv` giving its value, interval, sample size, the artifact file, the JSON path inside it, the pipeline script that produced it, and the SHA-256 prefix of that script. `notebooks/03_traceability.ipynb` resolves every row. `artifacts/run_log.csv` records each harness run. The exhibit generator reads only artifacts; the tables in the paper are its output, unedited.

## Pipeline

1. `code/pipeline/build_cores.py` — extracts the columns the analysis needs from the Crunchbase CSV dump into parquet (`P001_CORES`).
2. `code/pipeline/build_sample_v1.py` — builds the frozen analysis file (partner-attributed deals; SHA-256 prefix in `artifacts/sample_manifest.yaml`).
3. `code/pipeline/i73_… i82_…` — the pre-study harness (matching, gates, shock layer, exit battery, stage control); `gates.py`, `gates_lib.py`, `emit_contract.py` are their shared modules.
4. `code/pipeline/p001_00_… p001_59_…` — the paper's estimates, one script per run, each writing one JSON artifact through `emit_contract.emit`; `p001_rescue_common.py` and `p001_v6_common.py` hold the shared estimators (cell-demeaned FWL, cluster bootstrap, within-partner and within-round samples).
5. `code/public_sources/` — collection and matching of the public-source variables used in `p001_58` (fund-cycle controls, patents, balance).
6. `code/build/p001_09_exhibits.py` → `p001_09b_assemble_tables.py` — tables and figures from artifacts; `code/verification/` — checks run on the manuscript.

Environment variables used by the scripts: `CRUNCHBASE_RAW`, `P001_CORES`, `P001_SAMPLE`, `P001_OUT`, `P001_ARTIFACTS`, `P001_TABLES`, `P001_FIGURES`, `P001_PROJECT_ROOT`, `USPTO_RAW`, `SEC_CONTACT`, `CH_API_KEY`. Scripts and docstrings are partly in Korean, the project's working language; the paper and its exhibits are in English.

## Verification run against the manuscript

`code/verification/` holds the checkers run before submission. `ledger_lint.py` runs here as-is (`VERIFY_CONFIG=code/verification/verify_config.json`); the other three need the manuscript files, which are not part of this repository.

- `verify_draft.py` — every number in the prose must exist in the ledger or an artifact; retired artifacts are excluded from the pool.
- `ledger_lint.py` — claim ids unique; every ledger row's JSON path resolves and its value matches the artifact.
- `assert_anchors.py` — each headline claim is pinned to the artifact it must come from.
- `check_refs.py` — every section, table, panel and appendix reference resolves to an existing target.
